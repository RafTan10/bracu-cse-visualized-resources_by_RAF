Order of execution

This order explains most of the rules below.

FROM→WHERE→GROUP BY→HAVING→SELECT→ORDER BY→LIMIT
  • WHERE runs before grouping, so it can't use aggregates. Put AVG(x) > 5 in HAVING.
  • A SELECT alias works in ORDER BY (and HAVING in MySQL), but not in WHERE.
  • Every SELECT column that isn't aggregated must be in GROUP BY.

Lab 1: easy marks to lose

ALTER TABLE: five forms

GoalSyntax
New columnADD col TYPE
Change type onlyMODIFY col NEWTYPE
Rename (+type)CHANGE old new TYPE
Remove columnDROP COLUMN col
Rename tableRENAME TO newname

CHANGE always needs the type, even when the type stays the same.

Write it right on paper

  • Text and dates go in single quotes: 'Dhaka', '2020-01-01'
  • LIKE '%x' = ends with x · 'x%' = starts with · '_a%' = 2nd letter a
  • BETWEEN a AND b includes both ends, and a must be ≤ b
  • IS NULL / IS NOT NULL, never = NULL
  • UPDATE t SET c = expr WHERE …; with no WHERE changes every row
  • DELETE FROM t WHERE … removes rows · DROP TABLE t removes the table
  • Mixing AND/OR? Use brackets: a AND (b OR c)
  • DECIMAL(5,2) = 5 digits in total, 2 after the point (max 999.99)

Lab 2: aggregates

NULL behaviour

  • COUNT(*) counts rows. COUNT(col) skips NULLs.
  • AVG / SUM / MIN / MAX ignore NULLs.
  • MAX(date) gives the latest date, MIN(date) the earliest.

WHERE + GROUP BY + HAVING together

SELECT role, AVG(runs) FROM players
WHERE  debut_date >= '2020-01-01'  -- rows
GROUP BY role
HAVING AVG(runs) > 200;          -- groups

Lab 2: pick the pattern from the question's wording

Question says…Write
"the highest / lowest" (ties too)WHERE x = (SELECT MAX(x) FROM t)
"above average"WHERE x > (SELECT AVG(x) FROM t)
"more than every / all of group B"x > ALL (SELECT x … WHERE grp='B')
"more than at least one / any of B"x > ANY (SELECT x … WHERE grp='B')
"the best in each group"correlated: x = (SELECT MAX(x) FROM t t2 WHERE t2.g = t1.g)
"groups with at least one row where…"WHERE EXISTS (SELECT * … WHERE t2.g = t1.g AND …)
"max without MAX / using EXISTS"NOT EXISTS (… t2.id <> t1.id AND t2.x > t1.x)
"the unique max"same as above, but with t2.x >= t1.x
"the group with the most rows"HAVING COUNT(*) >= ALL (SELECT COUNT(*) … GROUP BY g)
"groups whose average beats the overall average"HAVING AVG(x) > (SELECT AVG(x) FROM t)
"groups that have no X"g NOT IN (SELECT g FROM t WHERE X)
subquery after FROMFROM (SELECT …) AS alias (the alias is required)
show one fixed value on every rowSELECT name, (SELECT MAX(x) FROM t) AS top
Trap 1: > ALL (subquery) where the subquery returns a NULL gives an empty result. Add AND col IS NOT NULL inside the subquery.
Trap 2: = (subquery) fails if the subquery returns more than one row. Use IN or = ANY.
Trap 3: ORDER BY … LIMIT 1 for "the highest" drops ties. Use = (SELECT MAX…).
Trap 4: > ANY = "more than the smallest". > ALL = "more than the biggest".
