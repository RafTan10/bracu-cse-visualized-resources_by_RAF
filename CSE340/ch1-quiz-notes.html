CPU time, CPI and clock rate

The core of the chapter. Three things set performance: IC (program, ISA, compiler), CPI (hardware, and the instruction mix), clock rate (hardware and technology). Improving one often worsens another, which is why questions say "but this increases CPI by 20%".

Pattern for "solve for the unknown": write T = IC × CPI / f for the old and the new machine, plug in the ratios (e.g. T_new = 0.7T, CPI_new = 1.2 CPI), and IC cancels. You get f_new = f × (CPI ratio) / (time ratio).

Slide examples (likely to be reused with new numbers)

Slide A runs in 10 s at 2 GHz. B must run in 6 s but needs 1.2× the cycles. Clock rate of B?
Cycles_A = 10 s × 2 GHz = 20 × 10⁹ Cycles_B = 1.2 × 20 × 10⁹ = 24 × 10⁹ f_B = 24 × 10⁹ / 6 s = 4 GHz
Slide A: 250 ps, CPI 2.0. B: 500 ps, CPI 1.2. Same ISA. Which is faster?
Time per instruction: A = 2.0 × 250 = 500 ps, B = 1.2 × 500 = 600 ps A is 600/500 = 1.2× faster

IC is assumed equal because the ISA is the same and it is the same program (and compiler).

SPEC benchmark and geometric mean

SPEC normalises each program's time to a reference machine, then summarises with the geometric mean so the result does not depend on which machine is the reference.

Watch out: the Q11 hint in the practice sheet writes ratio = execution / reference. The slides and textbook use SPECratio = Reference time / Execution time (higher = faster). Use the slide version and write the formula in your answer so the marker sees your method.
Q8 Why not the arithmetic mean? (A: 10 s, 100 s · B: 100 s, 10 s)
A as reference → B's ratios: 10/100 = 0.1, 100/10 = 10 AM = (0.1 + 10)/2 = 5.05 → "B is 5.05× faster than A" B as reference → A's ratios: 100/10 = 10, 10/100 = 0.1 AM = 5.05 → "A is 5.05× faster than B" ← contradiction GM: √(0.1 × 10) = 1 in both cases → "A and B are equal" ← consistent

Answer: No. The arithmetic mean of ratios changes its verdict depending on which machine is the reference. The geometric mean gives the same comparison whatever the reference, because GM(X/ref) ÷ GM(Y/ref) = GM(X/Y): the reference cancels.

Amdahl's law

Speeding up one part only helps in proportion to how much time that part takes. The unaffected part sets a hard floor. Corollary: make the common case fast.

T_new = T_affected / n + T_unaffected Max possible speedup (n → ∞) = T_old / T_unaffected "Impossible" proof: target time < T_unaffected → no n works
Slide Multiply takes 80 s of 100 s. Make the whole thing 5× faster?
20 = 80/n + 20 → 80/n = 0 → impossible
Q4 250 s program; add 70 s, sub 85 s, shift 40 s
a) Add reduced by 20% → saves 0.2 × 70 = 14 s → new total 236 s (5.6% less) b) 20% of 250 = 50 s to remove. Shift is only 40 s. Even removing shift completely leaves 210 s > 200 s → No
Q12 Deep learning epoch: CPU 25%, GPU 60%, I/O 15%. Target 3×
Target time = 100/3 = 33.33% a) 33.33 = 25 + 15 + 60/n → 60/n = −6.67 → impossible Unaffected part (40%) alone exceeds the target. Max speedup = 100/40 = 2.5× b) 33.33 = 25/5 + 15 + 60/n = 20 + 60/n → 60/n = 13.33 → n = 4.5×

Why MIPS is a bad metric

MIPS ignores how much work each instruction does. Three reasons to write in an answer:

  • It cannot compare computers with different ISAs: their instruction counts for the same task differ.
  • It ignores instruction complexity: one complex instruction may do the work of several simple ones.
  • CPI varies between programs on the same CPU, so one machine has no single MIPS value.

The only fair measure is execution time for the same task.

Q5 P1: 4 GHz, CPI 0.9, 5×10⁹ instr · P2: 3 GHz, CPI 0.75, 1×10⁹ instr
MIPS_P1 = 4×10⁹ / (0.9 × 10⁶) = 4444 MIPS_P2 = 3×10⁹ / (0.75 × 10⁶) = 4000 T_P1 = 5×10⁹ × 0.9 / 4×10⁹ = 1.125 s T_P2 = 1×10⁹ × 0.75 / 3×10⁹ = 0.25 s

P1 has the larger MIPS but P2 finishes 4.5× sooner. The claim is false.

Q10 Alex (Intel) vs Ben (AMD)
MIPS_Alex = 10×10⁹ / (5.0 × 10⁶) = 2000 MIPS_Ben = 15×10⁹ / (6.8 × 10⁶) = 2206 → Ben has higher MIPS

Agree with the third friend. The ISAs differ, so the compilers produced different instruction counts for the same sort. Ben's CPU ran more instructions per second but needed 50% more instructions, and took 6.8 s against Alex's 5.0 s. Alex's PC is 6.8/5.0 = 1.36× faster.

Power trend and the power wall

Dynamic power in CMOS: P = C × V² × f. Voltage is squared, which is why lowering voltage was the main way to keep power under control.

Slide New CPU: 85% of load, 15% lower voltage and frequency
P_new/P_old = 0.85 × 0.85² × 0.85 = 0.85⁴ = 0.52 → 48% less power
Q6 14.3% less load, 81.3% of voltage and frequency
P_new/P_old = 0.857 × 0.813² × 0.813 = 0.857 × 0.5374 = 0.4605 Power reduced by ≈ 53.9%

Note that "14.3% less" means multiply by 0.857, while "uses 81.3%" means multiply by 0.813. Read each wording carefully.

Q9 Explain the trend: clock speed → power wall → multicore
  • a) Execution time = IC × CPI / clock rate, so engineers raised the clock rate every generation (plus pipelining and ILP).
  • b) Power ∝ frequency. Higher clock means more power and more heat, and there is a limit to how much heat can be removed cheaply (air cooling).
  • c) They lowered the supply voltage (about 5 V down to about 1 V). Because power ∝ V², this cut power sharply and let frequency rise while total power grew only slowly.
  • d) Below about 1 V transistors leak too much: static (leakage) power rises and switching becomes unreliable. With voltage stuck and heat removal maxed out, clock rates hit the power wall around 2004. The industry switched to multicore: several slower, power-efficient cores per chip, which improves throughput but needs explicitly parallel programming (load balancing, communication, synchronisation).
Q13 2010 vs 2018 processor: capacitance, static share, voltage cut
a) C = P_dyn / (V² f) C_A = 110 / (1.3² × 4×10⁹) = 1.63 × 10⁻⁸ F C_B = 35 / (0.8² × 3×10⁹) = 1.82 × 10⁻⁸ F b) A: total 130 W, static 20/130 = 15.4%, static:dynamic = 20/110 = 0.18 B: total 50 W, static 15/50 = 30.0%, static:dynamic = 15/35 = 0.43 c) Target = 0.85 × 130 = 110.5 W. V_new = xV, static ∝ x, dynamic ∝ x² 110x² + 20x − 110.5 = 0 → x = 0.9155 V_new = 1.3 × 0.9155 = 1.19 V → reduce by ≈ 0.11 V (8.5%)

Take-away for theory: as voltage drops, static power becomes a larger share of the total (15% → 30%), which is the leakage problem behind the power wall.

Wafer, die, yield and cost

Die: one rectangular chip cut from the wafer. Yield: the fraction of dies on a wafer that work. Cost per die grows non-linearly with die area and defect rate.

Wafer area = π (diameter/2)² Die area = Wafer area / Dies per wafer Yield = 1 / (1 + D × A_die)^N Cost/die = Wafer cost / (Dies × Yield)
Q1A–B Define yield. Why "≈" in dies per wafer?

Yield is the percentage of good (working) dies out of all dies on the wafer. Defects from manufacturing make some dies unusable.

"≈" not "=": the wafer is circular but dies are rectangular, so partial dies around the edge are wasted. Space is also lost to scribe lines between dies and test structures. Wafer area ÷ die area therefore overestimates the real count.

Q1C–D Wafer X (19 cm, 89 dies, 0.023/cm², cost 20) vs Y (20 cm, 100 dies, 0.031/cm², cost 15), N = 2
X: area = π(9.5)² = 283.53 cm², die = 283.53/89 = 3.186 cm² Yield = 1/(1 + 0.023×3.186)² = 0.868 Cost/die = 20 / (89 × 0.868) = 0.259 Y: area = π(10)² = 314.16 cm², die = 3.142 cm² Yield = 1/(1 + 0.031×3.142)² = 0.830 Cost/die = 15 / (100 × 0.830) = 0.181

Y has the lower yield but is cheaper per die because the wafer costs less and holds more dies.

Short theory answers

Questions marked "Answer yourself" on the slides are prime short-question material.

Response time vs throughput

Response (execution) time: start to finish of one task. Throughput: work done per unit time.

Faster processor?

Improves both response time and throughput.

More processors for separate tasks?

Throughput improves; response time of a single task is unchanged (unless queueing delay was large).

Elapsed vs CPU time

Elapsed includes I/O, OS overhead and idle time. CPU time is only the time the CPU computes this task (user + system).

Which plane is "best"?

Depends on the metric: speed → Concorde (1350 mph); capacity and throughput → A380; range → 777-200LR. Performance must be defined first.

What sets IC, CPI, f?

IC: algorithm, language, compiler, ISA. CPI: hardware and instruction mix. Clock rate: hardware and technology.

Five classic components

Input, output, memory, datapath, control. Datapath + control = processor.

Levels of program code

High-level language → (compiler) → assembly → (assembler) → binary machine code.

System software

Compiler translates HLL to machine code. OS handles I/O, manages memory and storage, schedules tasks and shares resources.

Best performance measure

Execution time of real programs. MIPS and clock rate alone mislead.

Seven great ideas

IdeaOne-line meaning
AbstractionHide lower-level detail in layers to manage complexity
Make the common case fastOptimise the frequent operation (links to Amdahl)
ParallelismDo several operations at the same time
PipeliningOverlap stages of instructions (a form of parallelism, Chapter 4)
PredictionGuess ahead (e.g. branches) instead of waiting
Hierarchy of memoriesRegisters → cache → RAM → storage: fast and small to slow and large
Dependability via redundancyExtra components so one failure does not break the system

Mistakes that cost marks

Units. GHz → ×10⁹ Hz; ps → ×10⁻¹² s; ns → ×10⁻⁹ s. 10⁶ instructions at 2.7 GHz gives milliseconds, not seconds.
"n times faster" is slower time ÷ faster time. Never subtract.
"Reduce by 30%" → multiply by 0.7. "Uses 81.3%" → multiply by 0.813.
Power: square the voltage ratio, not the frequency.
Weighted CPI: weight by instruction count or fraction, not a plain average of class CPIs.
Yield formula: use the slide version, 1/(1 + D×A)^N, with the N they give.
Distractors: some given values are unused (Q15). Say so briefly rather than forcing them in.
Explain questions: one formula plus one sentence of reason beats a long paragraph.

Midterm practice

The midterm covers Chapter 1 (full), Chapter 2 slides 1–46 and Chapter 3 slides 9–21, from the handouts and the slides. Its formats are True/False, analytical, scenario-based justification, mathematical problems, coding and tracing. Mathematical problems are the worked questions above; coding and tracing come from Chapter 2. Answer each one on paper first, then open it.

True / False

T/F 1 CPU time = instruction count × CPI × clock cycle time.

True. The performance equation; ÷ clock rate instead of × cycle time is the same thing.

T/F 2 Doubling the clock rate always halves the execution time.

False. Only if instruction count and CPI stay the same; a faster clock often raises CPI, and I/O time doesn't shrink.

T/F 3 Adding more processors to a server improves throughput but not the response time of one task.

True. More work done per second; a single task still runs on one processor (slide 13).

T/F 4 MIPS is a fair way to compare computers with different instruction sets.

False. It ignores instruction count, and CPI differs by program (slide 29).

T/F 5 The geometric mean of SPEC ratios ranks computers the same whichever reference machine is used.

True. GM(a/r) ÷ GM(b/r) = GM(a/b): the reference cancels.

T/F 6 Dynamic power ∝ capacitive load × voltage² × frequency.

True. Slide 22.

T/F 7 Cutting capacitive load, voltage and frequency each by 15% leaves about 52% of the power.

True. 0.85 × 0.85² × 0.85 = 0.85⁴ ≈ 0.52 (slide 23).

T/F 8 Making one part of a task 10× faster makes the whole task 10× faster.

False. Amdahl's law: the unimproved part limits the speedup.

T/F 9 For a fixed defect density, a bigger die has a lower yield.

True. More area per die means more chance of a defect landing on it.

T/F 10 Elapsed time includes I/O and OS overhead; CPU time does not count waiting for I/O.

True. Slide 15.

T/F 11 A computer with a higher clock rate can still be slower.

True. If its CPI or instruction count is high enough, CPU time can be larger.

T/F 12 The move from single-core to multicore was mainly forced by power.

True. The power wall: clock rates couldn't keep rising (slides 24–25).

T/F 13 If A is 1.25 times faster than B, then B's execution time is 1.25 × A's.

True. Performance_A / Performance_B = Time_B / Time_A = 1.25.

T/F 14 Abstraction hides lower-level detail to manage complexity.

True. One of the seven great ideas.

Analytical

Analytical Why is multicore not a free performance gain?

Programs must be written explicitly in parallel. The programmer has to split the work, balance the load, and handle communication and synchronization between cores; a sequential program uses only one core.

Analytical Why is MIPS a misleading metric?

MIPS = instruction count ÷ (time × 10⁶). It ignores how many instructions a program needs (different ISAs need different counts) and how complex they are, and CPI changes from program to program, so a higher MIPS rating can mean a slower machine.

Analytical Why does die cost grow faster than die area?

A bigger die means fewer dies per wafer and a lower yield (more of them catch a defect). Both effects push cost per die up, so the relationship is nonlinear (slide 11).

Scenario-based justification

Scenario A CPU's clock goes from 2 GHz to 3 GHz, but a compiler change raises CPI from 1.5 to 2.4 for the same program. Is the new system faster? Justify.

No. Time per instruction = CPI ÷ clock rate: old 1.5 / 2 GHz = 0.75 ns, new 2.4 / 3 GHz = 0.80 ns. The new system is about 6.7% slower.

Scenario A program runs in 100 s, 80 s of it in multiplication. Can improving multiplication make it 5× faster? Justify.

No. 5× faster means 20 s. The other 20 s don't change, so multiplication would need 80/n + 20 = 20, i.e. zero time. Impossible (slide 28).

Scenario Machine X is rated 4000 MIPS and Y 2500 MIPS. X's ISA needs twice as many instructions for the same program. Which is faster? Justify.

Y. Time = IC ÷ (MIPS × 10⁶). X: 2·IC / 4000 = IC/2000; Y: IC/2500. Y's time is smaller, despite the lower MIPS.
