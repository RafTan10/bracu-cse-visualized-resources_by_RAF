Decisions and loops: branches, labels and the PC

So far every instruction ran once, top to bottom. Branches let the program skip code (if/else) or go back and repeat it (loops). The whole level comes down to one question: what's the next value of the PC?

You will be able toTranslate if, if/else, nested if, && and while/for loops into RISC-V
You will be able toPick the right branch every time by branching on the opposite condition
You will be able toFill in instruction addresses and branch offsets (Q8, Q9)
Level 2 isn't marked finished on this device yet. Loops use ld, sd and A[i] from Level 2, so it helps to do Level 2's check first.

2Drill: which branch skips the body?

The most common mistake in this chapter is branching on the wrong condition. Practise until it's automatic: you branch to skip the body when the condition is false.

Traps that cost marks

WrongRight
if (i == j) → beq i, j, ElseBranch to skip when the condition is false: bne i, j, Else.
No jump after the then-partEnd the then-part with beq x0, x0, Exit, or it falls straight into the else-part.
if (a > b) → bgt as if it were a real instructionOnly beq, bne, blt, bge (and bltu, bgeu) exist. Swap the operands: skip with bge b, a. bgt and ble are assembler shortcuts (pseudo-instructions).
Putting the loop's initialisation under the Loop: labelInitialise once, before the label (Loop Examples: "initialization happens once"). Otherwise i resets on every pass.
Forgetting the update or the jump backA loop needs: test at the top, body, update (addi i, i, ±1), beq x0, x0, Loop.
Branch offset counted in instructionsIn bytes: target address − branch address. Backwards is negative. 3 instructions back = −12.
Giving a label its own address in the tableA label has no address of its own. It names the instruction right after it (Q9: Exit = 80024).
&& written as one branchTwo branches, both jumping to the same skip label (Q14). Either condition false means skip.
Using blt to compare unsigned numbersblt/bge compare as signed. Use bltu/bgeu for unsigned (slide 35).

A register is just 64 bits. This level is about what those bits mean (unsigned or signed), how to change them (shifts, and, or, xor), and how to get a constant bigger than 12 bits into a register (lui + addi).

Traps that cost marks

WrongRight
addi x20, x20, 3135addi's constant is 12-bit signed: −2048 to 2047. If the low 12 bits are 0x800 or more, add 1 to lui's part and use a negative addi.
Using srli to halve a negative numbersrli fills with 0s, so it only divides unsigned or non-negative values (slide 26). srai keeps the sign.
Thinking 1000 0000 is −0It's −128, the most negative 8-bit value. Two's complement has only one zero.
Writing not x9, x10 as a real instructionRISC-V has no NOT. Use xori x9, x10, -1 (xor with all 1s, slide 29).
Sign-extending with lbulbu fills the top with 0s (zero extension). lb copies the sign bit (slide 17).
Counting bit positions from the leftBit 0 is the rightmost bit. "Bits 4 and 5" is mask 0011 0000.
Forgetting that lui clears the low 12 bitslui rd, U sets rd = U × 4096 (bits 11–0 become 0), then addi adds the low part.
Using mul when the question says "without multiplication"Split the constant into powers of 2: 19a = 16a + 2a + a (slli 4, slli 1, add, add).
Errors in the course material. (1) Slide 13 gives the 64-bit unsigned maximum as 18,446,774,073,709,551,615. The correct value is 18,446,744,073,709,551,615 (2⁶⁴ − 1). (2) The faculty's Q10 answer uses addi x20, x20, 3135, which doesn't fit in addi's 12-bit signed constant. See the Q10 card above for the version that works on real RISC-V.

Machine code: every instruction is 32 bits

The computer stores instructions as numbers, just like data. This level shows how each instruction becomes 32 bits: which fields it has, where the registers go, and how branch offsets get cut up and scattered. Then you'll go the other way and decode hex back to assembly.

You will be able toName the format of any instruction and write its fields in the right order
You will be able toEncode S, SB and UJ immediates, writing X where the opcode or funct isn't given
You will be able toDecode hex machine code and find where a branch's label is (Q16)
Level 4 isn't marked finished on this device yet. Encoding uses two's complement and hex from Level 4, so it helps to do Level 4's check first.

Traps that cost marks

WrongRight
Giving the byte offset when asked for a branch's "immediate"In this course the immediate is the byte offset ÷ 2 (target = PC + immediate × 2, slide 43). Offset 12 → immediate 6. Write both: "offset 12 bytes, so immediate = 6".
funct7 · rs1 · rs2 · …Left to right it's funct7 · rs2 · rs1 · funct3 · rd · opcode. rs2 comes first (R, S and SB).
Giving sd an rd fieldS-type has no rd. The value register goes in rs2, the base in rs1, and the 12-bit offset is split into imm[11:5] and imm[4:0].
Storing the branch offset in instructionsThe offset is in bytes. Write it as 13 bits, drop bit 0 (it's always 0), and scatter the rest: imm[12] · imm[10:5] · … · imm[4:1] · imm[11].
Putting imm[11] next to imm[12]In SB, imm[11] goes in bit 7, right before the opcode. In UJ, imm[11] sits between imm[10:1] and imm[19:12].
Positive bits for a backward branchA backward branch has a negative offset, so write it in two's complement. −20 → 1 1111 1110 1100.
Inventing opcode or funct valuesUse exactly the values the question gives. If it gives none, write X for every bit.
slli with a 12-bit immediateShifts use funct6 (6 bits) and a 6-bit shamt, because 63 is the largest useful shift and fits in 6 bits (handout).
Reading hex digits as decimalEach hex digit is exactly 4 bits. 0x015A04B3 = 0000 0001 0101 1010 0000 0100 1011 0011.
Errors in the course material. (1) Q20's second part asks for BNE x10, x11, but the faculty's solution encodes rs2 = 00000 and rs1 = 00110 (x0 and x6). The immediate bits are right, and the correct register fields are rs2 = 01011 and rs1 = 01010. (2) In Q16, the given hex 0x015B1A67 has funct3 = 001, which is the sheet's code for BNE. BGE's real funct3 is 101. The offset (20) is unaffected. (3) The handout's ld example ends with 00AB2A833, which has one digit too many. The answer is 0x00AB2A83. (4) The slides give no opcodes. The sheet's branch opcode 103 (1100111) is official RISC-V's jalr opcode. The official branch opcode is 99 (1100011). In your exam, use whatever the question gives.

Procedures and the stack, plus the rest of Chapter 2

A procedure is a piece of code you can call from anywhere and come back from. The hard part is the bookkeeping: where the arguments go, how the code gets back, and which registers have to be saved on the stack. After that, a quick sweep of the chapter's remaining theory: synchronization, linking and loading, the sort example, arrays vs pointers, x86, and fallacies.

You will be able toCall and return with jal / jalr, and pass arguments in x10–x17
You will be able toPush and pop registers on the stack, and know which ones must be saved
You will be able toWrite leaf and non-leaf procedures (Q5, Q17, Q22), and answer the theory questions
Level 5 isn't marked finished on this device yet. This level doesn't need encoding, so you can go straight on.

1Watch

Eight scenes. The right side shows the stack growing down from address 8000, with sp marked. Watch x1 (the return address) closely: forgetting to save it is the classic procedure bug, and scene 7 shows what happens.

2Code lab: procedures with a real stack

sp (x2) starts at 8000 and the stack has room for 16 doublewords below it. For whole programs, end main with beq x0, x0, Exit so it doesn't run into the procedure, the way the handout does. For "procedure only" questions, the lab calls your procedure for you and checks that it returns. The tests check the result, that sp comes back to 8000, and that registers you must preserve keep their values.
